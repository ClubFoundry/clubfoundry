# Исходный код установщика ClubFoundry

[English version](README.md) | [Описание проекта](../README.ru.md) |
[Установка приложения ClubFoundry](../INSTALLATION.ru.md)

> Эта страница является технической документацией публичного исходного кода
> установщика `installer/install.sh`, а не пользовательской инструкцией по
> установке приложения ClubFoundry. Чтобы установить ClubFoundry на TrueNAS
> SCALE или другой Linux-сервер с Docker, используйте
> [инструкцию по установке приложения](../INSTALLATION.ru.md).
>
> Готовый офлайн-комплект `clubfoundry-VERSION-offline.tar.gz`, опубликованный в
> GitHub Release, уже содержит этот установщик. При установке из готового
> комплекта отдельно скачивать или устанавливать установщик не нужно: распакуйте
> комплект и запустите входящий в него `install.sh` по
> [инструкции по установке приложения](../INSTALLATION.ru.md).

В этой папке находится публичный исходный код установщика ClubFoundry. Он
проверяет сервер, получает образы приложения с контролем целостности, выбирает
постоянное хранилище, создаёт конфигурацию Docker Compose и запускает основное
приложение вместе с сайдкаром ClubFoundry.

`installer/install.sh` является каноническим публичным исходным кодом
установщика.

## Запуск установщика

Сначала скачайте скрипт, чтобы его можно было просмотреть:

```bash
curl -fL \
  https://raw.githubusercontent.com/ClubFoundry/clubfoundry/main/installer/install.sh \
  -o install.sh
less install.sh
sudo bash install.sh
```

При новой интерактивной установке нужно выбрать личное некоммерческое либо
коммерческое/профессиональное использование конкретного инстанса. Для
автоматической установки задайте режим явно:

```bash
sudo bash install.sh --usage-mode=noncommercial
sudo bash install.sh --usage-mode=commercial
```

Данные API TrueNAS вводятся в браузере при первом запуске, а не передаются как
обычные открытые аргументы командной строки.

## Режим развёртывания

Рекомендуемый вариант состоит из приложения и сайдкара `clubfoundry-updater`
под управлением Docker Compose. Сайдкар выполняет проверяемые обновления, откат,
восстановление, защиту от циклических падений и сбор диагностики.

Если Compose недоступен, установщик использует один контейнер без сайдкара.
Этот режим также можно явно выбрать параметром `--mode=a`.

Веб-интерфейс использует порт 3000 или другой свободный порт, если 3000 занят.
Порт можно указать параметром `--port=N`.

## Постоянные данные

На TrueNAS установщик предпочитает пул, назначенный службе Apps. Если пул Apps
не выбран, автоматический выбор выполняется только при наличии одного
подходящего подключённого ZFS-пула. При нескольких пулах укажите путь явно:

```bash
sudo bash install.sh --app-dir=/mnt/POOL/clubfoundry
```

На другом Linux-сервере с Docker всегда указывайте постоянный абсолютный путь,
например `--app-dir=/srv/clubfoundry`.

## Офлайн-комплект из GitHub Release

Готовый автономный комплект уже содержит образы приложения и сайдкара и
использует тот же установщик. В стандартном режиме Docker Compose установщик
разворачивает оба контейнера, поэтому отдельно скачивать или устанавливать
сайдкар не нужно:

```bash
tar -xzf clubfoundry-VERSION-offline.tar.gz
cd clubfoundry-VERSION-offline
sudo bash install.sh --offline="$PWD"
```

До загрузки образов установщик сверяет `MANIFEST`, `install.sh` и архивы
образов с внутренним файлом `SHA256SUMS`.

## Другие параметры

- `--channel=stable|beta|lts`
- `--link-token=cflink_...`
- `--offline=/абсолютный/путь/к/комплекту`
- `--app-dir=/абсолютный/постоянный/путь`
- `--port=N`
- `--usage-mode=commercial|noncommercial`
- `--update`
- `--dry-run`
- `--help`

Неизвестные параметры отклоняются до изменений на сервере. `--dry-run`
показывает рассчитанный план, не записывая файлы, не загружая образы и не меняя
контейнеры.

Параметр `--clean-install` намеренно удаляет существующую базу данных и
состояние ClubFoundry после проверки принадлежности одноимённых контейнеров.
Его нельзя использовать как обычную команду обновления.

## Обновление

```bash
sudo bash install.sh --update
```

Для офлайн-обновления используйте установщик из нового комплекта:

```bash
sudo bash NEW-BUNDLE/install.sh --update --offline=/абсолютный/путь/к/NEW-BUNDLE
```

## Проверка исходного кода

Быстрые проверки не обращаются к Docker и TrueNAS:

```bash
bash -n installer/install.sh installer/test-fresh-install-e2e.sh
sh -n installer/bootstrap.sh
bash installer/install.sh --help
bash installer/test-installer-contracts.sh
```

`test-fresh-install-e2e.sh` является привилегированным тестом для явно
настроенной одноразовой системы TrueNAS. Перед запуском изучите заголовок
скрипта и переменные окружения. Никогда не направляйте его на систему клиента.
